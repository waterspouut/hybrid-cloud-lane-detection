제시해주신 상세 목차는 40페이지 이상의 고품질 결과보고서를 작성하기에 아주 훌륭한 뼈대입니다. 이 목차를 기반으로 실제로 내용을 채워 나가는 구체적인 전략과 가이드를 제시해 드리겠습니다.

핵심은 **"텍스트로만 페이지를 채우려 하지 말고, 시각 자료(그림, 코드, 표, 그래프)를 중심에 두고 글을 써 내려가는 것"**입니다.

## [캡스톤 디자인 최종 보고서 작성 가이드 전략]

### 1. 기본 원칙: "Show, Don't Just Tell" (말하지 말고 보여줘라)

40페이지를 "우리는 ~를 했다"라는 줄글로만 채우는 것은 불가능하며 읽는 사람도 지루합니다. 페이지를 효율적이고 전문적으로 채우는 비결은 다음과 같습니다.

1.  **증거 우선 배치:** 각 소단락의 핵심이 되는 스크린샷, 아키텍처 다이어그램, 코드 스니펫, 그래프를 먼저 페이지에 배치합니다.
2.  **설명 추가:** 배치된 자료가 무엇인지, 어떤 의미를 가지는지, 왜 이렇게 설정했는지를 상세히 설명하는 글을 앞뒤로 붙입니다.
3.  **캡션 활용:** 모든 그림과 표에는 반드시 번호와 제목(캡션)을 답니다. (예: `[그림 Ⅲ-5] AWS EC2 인스턴스 보안 그룹 인바운드 설정 화면`)

### 2. 챕터별 상세 작성 전략 (목차 기반)

제시해주신 목차의 각 항목에 무엇을 넣어야 분량과 퀄리티가 확보되는지 구체적으로 짚어드립니다.

#### **Ⅰ. 서론 (예상 분량: 4~5 페이지)**

- **전략:** 문제를 최대한 심각하고 구체적으로 묘사하여 프로젝트의 필요성을 강조합니다.
- **내용 채우기:**
  - **1.1:** 관련 통계 자료(청년층 중고차 구매율, 사고율 등 기사나 통계청 자료 인용)를 그래프로 만들어 넣으면 좋습니다.
  - **1.2:** 실제 스마트폰 네비게이션 실행 화면과 기존 블랙박스 앱 실행 시 문제점(화면 가림 등)을 비교하는 사진을 넣으세요.
  - **2.1~2.3:** 우리가 앞서 대화하며 정리했던 내용들을 잘 다듬어서 넣습니다. (글 위주)
  - **3.2:** 목표 성능 지표를 표(Table)로 정리하여 제시합니다. (예: 추론 속도 < 200ms, 시스템 가동률 > 99.9%)

#### **Ⅱ. 시스템 설계 및 아키텍처 (예상 분량: 6~8 페이지)**

- **전략:** "왜?"에 대한 답변이 핵심입니다. 설계의 타당성을 증명해야 합니다.
- **내용 채우기:**
  - **1.2 전체 구성도:** 앞서 제가 그려드린(혹은 직접 그리신) 고퀄리티 아키텍처 다이어그램을 한 페이지 가득 넣습니다. 그리고 각 구성 요소 간의 화살표 흐름을 상세히 글로 풀어서 설명합니다.
  - **2.1 & 2.2 리소스 역할:** 리소스 목록을 표(Table)로 정리하고, 왜 하필 EC2의 특정 타입을 골랐는지, 왜 GCE SQL을 썼는지 기술적인 이유를 덧붙입니다.
  - **3. 세부 설계 고려사항:** 이 부분이 중요합니다. 대안 기술(예: 엣지에서 전부 처리하기, 클라우드 하나만 쓰기)과 비교했을 때 우리 방식의 장점을 논리적으로 설명합니다. (비교 표 활용 추천)
  - **4. 네트워크 설계:** VPC 내부 구조도(서브넷, 라우팅 테이블, 보안 그룹 연결 관계)를 다이어그램으로 그려 넣고 설명합니다.

#### **Ⅲ. 핵심 기술 구현 상세 (예상 분량: 15~20 페이지) ★가장 중요**

- **전략:** "이 보고서만 보면 따라 만들 수 있을 정도"로 자세히 적습니다. 스크린샷과 코드가 가장 많이 들어가는 챕터입니다.
- **내용 채우기:**
  - **1.1 개발 환경:** 사용한 장비 스펙 표(GPU, CPU, RAM), `nvidia-smi` 터미널 캡처 화면 등을 넣습니다.
  - **1.2 데이터 수집:** 실제 수집한 도로 주행 영상 샘플 캡처, Roboflow에서 바운딩 박스를 친 작업 화면 캡처를 여러 장 넣습니다. 데이터셋 통계(차량 몇 장, 차선 몇 장) 그래프도 좋습니다.
  - **1.3 모델 학습:**
    - YOLOv8 구조도 그림 삽입.
    - 학습 실행 명령어(CLI)와 설정 파일(`data.yaml` 등) 내용 코드 블록으로 삽입.
    - **중요:** 학습 과정에서 출력되는 Loss 그래프(점점 떨어지는 그래프)와 mAP 그래프(점점 올라가는 그래프) 캡처는 필수입니다. 페이지 채우기에도 아주 좋습니다.
  - **2. AWS 구축:**
    - AWS 콘솔 화면 캡처의 향연이어야 합니다. VPC 생성 화면, 서브넷 설정 화면, EC2 생성 시 옵션 선택 화면, 보안 그룹 규칙 설정 화면 등을 단계별로 캡처해서 넣고 설명을 답니다.
    - **2.2.2 Flask 코드:** 핵심적인 추론 부분 파이썬 코드를 주석과 함께 넣습니다.
  - **3. 엣지 앱:**
    - 안드로이드 스튜디오 프로젝트 구조 캡처, 앱 실행 화면(백그라운드 작동 알림창 등) 캡처.
    - 카메라 캡처 및 HTTP 전송 부분의 핵심 Java/Kotlin 코드를 넣습니다.
  - **4. GCE 데이터 파이프라인:**
    - GCP 콘솔 화면(VM, SQL 생성).
    - **4.2 ETL 스크립트:** 파이썬 ETL 전체 코드를 기능별로 나누어 설명하며 넣습니다.
    - **4.4 DB 스키마:** ERD(Entity Relationship Diagram) 다이어그램이나 테이블 명세서를 표로 넣습니다.

#### **Ⅳ. 시스템 테스트 및 결과 분석 (예상 분량: 8~10 페이지)**

- **전략:** 객관적인 수치와 시각 자료로 성능을 증명합니다.
- **내용 채우기:**
  - **1. AI 성능 평가:**
    - 테스트 데이터에 대한 추론 결과 이미지(바운딩 박스가 잘 쳐진 주간/야간 사진들)를 갤러리 형태로 여러 장 배치합니다.
    - Confusion Matrix나 PR Curve 그래프를 넣고 분석합니다.
  - **2. 클라우드 성능 테스트:**
    - JMeter 설정 화면 캡처.
    - **핵심:** 부하 테스트 중 AWS CloudWatch 모니터링 화면(CPU 사용률이 치솟고, Auto Scaling으로 인스턴스 개수가 늘어나는 그래프) 캡처는 시스템 안정성을 증명하는 최고의 자료입니다.
  - **3. 데이터 안정성:** AWS S3에 파일이 쌓인 화면과 GCE DB에 데이터가 들어온 SQL 조회 결과 화면을 나란히 보여주며 데이터가 잘 넘어왔음을 증명합니다.

#### **Ⅴ. 결론 및 제언 (예상 분량: 2~3 페이지)**

- **전략:** 프로젝트를 요약하고 솔직한 회고를 담습니다.
- **내용 채우기:** 서론에서 세웠던 목표를 얼마나 달성했는지 평가하고, 아쉬웠던 점(예: 엣지 기기 발열 문제 등)을 솔직하게 적은 뒤 향후 개선 방안을 제시하며 마무리합니다.

### 3. 작성 팁 및 유의사항

- **코드 블록 활용:** 소스 코드는 반드시 별도의 스타일(바탕색, 폰트)을 적용하여 본문과 구분합니다. 너무 긴 코드는 핵심만 추리고 전체는 부록으로 뺍니다.
- **글자 크기 및 줄 간격:** 학교/기관의 양식을 따르되, 너무 빽빽하지 않게 설정하여 가독성을 높입니다. (보통 줄 간격 160%~180% 사용)
- **학술적 어투:** '~했다', '~함' 보다는 '~하였다', '~를 수행하였다', '~로 분석된다'와 같은 객관적이고 학술적인 어투를 사용합니다.
- **페이지 번호 및 목차 업데이트:** 문서 작성이 끝나면 반드시 전체 목차의 페이지 번호를 업데이트합니다.
